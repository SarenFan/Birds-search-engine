# Alpha Tuning Report — Hybrid Search

## 1. Mục tiêu

Tìm trọng số alpha tối ưu cho công thức Hybrid Search:

```
hybrid_score = α × BM25_normalized + (1 - α) × Vector_normalized
```

- **α = 1.0**: Chỉ dùng BM25 (lexical search)
- **α = 0.0**: Chỉ dùng Vector (semantic search)
- **α = 0.5**: Cân bằng cả hai (mặc định ban đầu)

## 2. Phương pháp thực nghiệm

- **Bộ test:** 20 queries đa dạng chủ đề (từ `evaluation.py`)
- **Metrics:** Precision@10, Recall (pooling-based), F1-score
- **Alpha range:** 0.0 → 1.0 (bước 0.1) — tổng 11 giá trị
- **Phương pháp đánh giá relevance:** Keyword-based matching — document được coi là relevant nếu chứa ≥1 từ khóa trong danh sách relevant_keywords của query
- **Recall pooling:** Tổng số relevant documents = union tất cả relevant docs từ kết quả retrieval

### Lưu ý về methodology

Phương pháp pooling-based recall có bias: chỉ đánh giá trên documents đã được retrieve bởi ít nhất một method. Documents relevant nhưng không nằm trong pool sẽ bị bỏ qua. Đây là hạn chế chung của auto-evaluation khi không có human-labeled ground truth.

## 4. Phân tích kết quả

### 4.1 Xu hướng chính

Kết quả chia thành **3 nhóm rõ rệt:**

| Nhóm | Alpha range | F1 | Nhận xét |
|------|-----------|------|----------|
| Vector-dominant | 0.0 - 0.4 | 0.995+ | Precision và Recall đều rất cao |
| Cân bằng | 0.5 | 0.956 | Giảm đáng kể so với nhóm trên |
| BM25-dominant | 0.6 - 1.0 | 0.880 | Precision và Recall đều thấp nhất |

### 4.2 Tại sao Vector Search chiếm ưu thế?

1. **Model Vietnamese-bi-encoder:** Project sử dụng model `bkai-foundation-models/vietnamese-bi-encoder` (768 dimensions) — model chuyên biệt cho tiếng Việt, cho embedding quality cao hơn nhiều so với model đa ngôn ngữ.

2. **Đặc điểm corpus Voz:** Forum có nhiều bài viết sử dụng ngôn ngữ tự nhiên, đa dạng cách diễn đạt. Ví dụ: "laptop gaming" có thể được gọi là "máy tính chơi game", "pc game", "máy chơi game" — Vector bắt được tất cả.

3. **Keyword-based evaluation bias:** Phương pháp đánh giá bằng keyword matching có xu hướng ưu tiên Vector vì Vector tìm được nhiều docs liên quan (chứa keyword) mà BM25 bỏ lỡ do khác surface form.

### 4.3 Chọn alpha tối ưu: **α = 0.3**

Mặc dù α=0.0 cho F1 cao nhất (0.9975), nhưng chọn **α = 0.3** vì:

1. **Hybrid mới đúng nghĩa:** α=0.0 thực chất là Vector-only, không phải hybrid. Mục tiêu M3 yêu cầu "kết hợp kết quả từ BM25 và Vector".

2. **F1 gần như tương đương:** α=0.3 đạt F1 = 0.9950 — chỉ thấp hơn 0.0025 so với α=0.0.

3. **BM25 bổ sung exact-match:** 30% BM25 giúp ưu tiên kết quả chứa chính xác từ khóa user nhập, quan trọng cho các query chứa tên riêng, mã sản phẩm, v.v.

4. **Robustness:** Hybrid với BM25 component giúp hệ thống hoạt động tốt hơn khi Vector model bị sai (edge cases, OOV words).

## 5. Kết luận

- **Alpha tối ưu = 0.3** (30% BM25 + 70% Vector) đã được xác định qua grid search trên 20 queries
- Giá trị này được cập nhật làm default trong Web UI hybrid search
- User vẫn có thể điều chỉnh alpha từ 0.0 đến 1.0 qua slider trên giao diện
- Vector Search đóng vai trò chính nhờ model Vietnamese-bi-encoder chuyên biệt cho tiếng Việt
- BM25 vẫn cần thiết cho exact-match và tăng robustness
